### [ ] C-01 零点标定

- **为什么**：`g(q)` 用的是 URDF 关节角，而电机编码器给的是原始角。没标定 → g(q) 全错

### [ ] C-09 ⭐ **用轨迹的解析加速度（不用数值差分）**

- **什么时候做**：真机重力补偿阶段，需要启用 `full_dynamics` 模式时
- **为什么**：
  ```
  对 q 二次差分  → q̈ 噪声 23.8 rad/s² → 力矩噪声 5.44 N·m
  对 dq 一次差分 → q̈ 噪声  2.44 rad/s² → 力矩噪声 0.56 N·m
  轨迹解析加速度 → q̈ 噪声  0
  真实惯性项（1 rad/s²）= 0.23 N·m
  ```
  **数值差分的噪声比信号大 24 倍，完全不可用。**
- **怎么做**：
  - 五次多项式：`q̈(t) = 20a₅t³ + 12a₄t² + 6a₃t + 2a₂`
  - Fourier 轨迹：`q̈ = -Σ ω²[a·sin(ωt) - b·cos(ωt)]` 超简单
  - JTC 的下发轨迹要能取到当前时刻的解析 q̈（可能需要自己实现控制器）
- **退化方案**：真的拿不到轨迹时，用 5 Hz 一阶 IIR 低通（Mockway 方案），
  但只适合 < 1 rad/s 的慢速运动
- **验收**：full_dynamics 模式下，力矩噪声 < 0.1 N·m

#### C-17 补充调研（2026-11-07）：OPW 解析 IK 的适用性

**结论：结构完全符合 OPW 假设，参数需标定，暂不实施。**

实测验证（用我们的 URDF，q=0 姿态）：

| OPW 前提 | 我们的臂 | 实测 |
|---|---|---|
| 正交-平行基座：J1 ⟂ J2 | J1=(0,0,1), J2=(−1,0,0) | dot = **0.000000** ✅ |
| J2 ∥ J3 | J2=(−1,0,0), J3=(1,0,0) | cross = **0** ✅（**反平行**，dot = −1） |
| 球腕：后三轴共点 | J4/J5/J6 | 轴线距离 J4-J5 = **0**、J5-J6 = **0**、J4-J6 = **0** ✅ |

即满足论文 *"Ortho-parallel Basis + Spherical Wrist"* 的两个条件
（[OPW](https://github.com/Levi-Armstrong/opw_kinematics)）。

**候选几何参数**（从 URDF 读出，需与论文定义核对）：

| 参数 | 我们测得 |
|---|---|
| a1（基座→肩 x 偏移） | 0 |
| a2（大臂长度） | 0.22 |
| b（侧向偏移） | 0 |
| c1（肩高） | 0.06 |
| c2（J3→J4） | 0.0955 |
| c3（J4→腕心） | 0.1205 |
| c4（法兰偏移，tool0 与腕心重合） | 0 |

**三个必须解决的问题**：

1. **零位不同**：OPW 要求零点时手臂**竖直向上**；我们 q=0 时手臂**水平伸展**
   （末端 (0, −0.4985, 0.06)，g(q=0)[1] = 5.535 N·m 证明是水平）→ `offsets` 必须标定
2. **J2/J3 反平行** → 需要 `sign_corrections[?] = −1`
3. **基座坐标系朝向不同**：我们沿 −Y 伸展，OPW 用论文约定系 →
   需要在 `Parameters` 外层包一层 `T_base_opw` / `T_tool_opw` 变换

**标定方法：数值拟合，不手推**（手推符号组合有 2⁶ × 连续偏移，几乎必错）

```python
def cost(x):
    params, offsets, signs = decode(x)
    err = 0.0
    for q in random_configs:              # 100 组随机 q
        T_pin = pinocchio_fk(model, q)    # 真值
        T_opw = opw.forward(params, signs * (q - offsets))
        err += np.linalg.norm(T_pin - T_opw)
    return err
# scipy.optimize.minimize(cost, x0, method='L-BFGS-B')
```

**验收**：`cost < 1e-9`（说明参数完全对上）。

**暂不做的理由**：
- 当前不需要 IK（`jog.py` 直接发关节角）
- 参数标定成本高（7 参数 + 6 offsets + 6 signs + 基座变换）
- 真要 IK 时，Pinocchio 阻尼最小二乘约 60 行即可，精度更高
- 本地未装 `opw_kinematics`，需先 clone + build

**什么时候才值得做**：
- 需要"末端到某位姿"且对求解速度有要求（OPW ~0.1 µs vs 迭代法 ~100 µs）
- 需要在 MCU 上跑 IK（只有解析解可行）
- 需要枚举全部 8 组解做碰撞筛选（OPW 天然给全解）

### [ ] C-18 自写轨迹控制器，替换 JTC 并**暴露解析 q̈**

- **状态**：⏸ **暂缓**（当前 JTC + 重力补偿已够用；等做 `full_dynamics` 时启用）
- **前置**：C-09（解析加速度）、C-16（dynamics.hpp）、C-04（在线重力补偿）

#### 为什么需要它

```
JTC 内部有插值  →  但**不对外暴露 q̈**
      ↓
我们只能拿到 pos_commands_（每 4 ms 一个位置）
      ↓
想算 q̈ 只能差分 → 噪声
```

这是 **C-09「用轨迹的解析加速度」的直接卡点**：
- 差分**测量值** → q̈ 噪声 23.8 rad/s²，力矩噪声 **5.44 N·m**（比真实惯性项 0.23 大 24 倍）❌
- 差分 **JTC 的平滑命令** → 噪声小一个量级，但仍非解析 ⚠️
- **自写控制器暴露解析 q̈** → 噪声 0 ✅

#### 做什么

```
hw_arm_controllers/
└── src/hw_arm_trajectory_controller.cpp   ← 新增包
    · 实现 controller_interface::ControllerInterface
    · 导出命令接口：position / velocity / **acceleration**
    · 用 algo 的 trajectory.hpp 生成轨迹：
        QuinticSegment  → q(t), q̇(t), q̈(t)  全解析
        FourierTrajectory → 同上
    · 每个控制周期写三个量，全部给硬件层
```

#### 数据通路

```
ros2 action / 自定义 action
        │ 目标 q_des（或末端位姿 → IK → q_des）
        ▼
hw_arm_trajectory_controller            ← 自写，替换 JTC
   · QuinticSegment::fit(q_cur, q_des, T)
   · 每 4 ms: evaluate(t) → q, dq, ddq
        │
        ├── position[q]
        ├── velocity[dq]
        └── acceleration[ddq]   ← **JTC 没有的关键量**
                ▼
hw_arm_hardware::write()
   · position → MIT 的 p_des
   · velocity → MIT 的 v_des
   · tau_ff   = g(q)                              （C-04）
              + friction(dq)                        （C-10）
              + rnea(q, dq, ddq) - g(q)             （C-16，可选）
                ▼
            MIT 帧 → CAN → 电机
```

#### 关键技术点

1. **`acceleration` 是 ros2_control 的标准命令接口名**
   ```cpp
   #include "hardware_interface/types/hardware_interface_type_values.hpp"
   hardware_interface::HW_IF_ACCELERATION   // "acceleration"
   ```
   硬件端需要**额外 export** 一个 `acceleration` 命令接口（现在只有 position/velocity/effort）。

2. **控制器必须 chainable 或直接对接硬件**
   - 方案 A：直接替换 JTC（控制器直连硬件接口）✅ 简单
   - 方案 B：用 chainable controller 串在 JTC 后面 ❌ 拿不到 JTC 的 q̈，无意义

3. **实时安全**
   - `QuinticSegment` 的系数在**收到新目标时**算一次（非实时线程）
   - 实时循环里只做 `evaluate()`（几次乘加，无分配）

4. **轨迹约束检查**（发之前）
   - 关节限位（URDF）
   - 速度上限 ≤ 0.3 rad/s（实测安全值）
   - 加速度上限 ≤ 2.0 rad/s²
   - 超限则延长 T 或拒绝

5. **与 JTC 的兼容**
   - 保留 JTC 作为备选（`controller_manager` 运行时切换）
   - 自写控制器出问题时可以切回 JTC

### [ ] C-19 接触过渡策略（四阶段 + S 型参数平滑）

- **状态**：⏸ **暂缓**（做力控时才需要，与 C-16 同批）
- **前置**：C-16（dynamics）、C-18（控制器）、**某种力感知能力**（见下）
- **来源**：达妙教程 F03「8.2 接触过渡策略」
- **📎 参数约束检查**：见本文件 C-20 末尾「附：阻抗参数约束检查（C-19/C-20 共用）」

#### 为什么需要

> 原文：**"接触过渡是力控中最危险的阶段。"**

```
自由空间 → 接触瞬间：冲击力 = m_eff · v_0 / Δt
                     速度 20mm/s、Δt 1ms、m_eff 5kg → 100 N 冲击
                     → 力控器根本来不及反应
```

**所以不能"直接碰上去"，必须分阶段过渡。**

#### 四阶段策略（原文数值）

| 阶段 | 内容 | 参数 | 目的 |
|---|---|---|---|
| **Phase 1 接近** | 自由空间逼近 | `v_approach ≤ 20 mm/s`<br>`K_d ≈ 500 N/m`（中等） | 缓慢接近，减小冲击 |
| **Phase 2 接触检测** | 力阈值 `\|f\| > f_threshold`（**2~5 N**）<br>或动量观测器残差 > 阈值 | **延迟 < 10 ms**（关键！延迟越大冲击越大） | 立即响应 |
| **Phase 3 冲击吸收** | 切换到低刚度 + 高阻尼 | `K_d = 50~100 N/m`<br>`ζ = 1.5`（过阻尼）<br>持续 50~200 ms | 吸收冲击能量 |
| **Phase 4 稳定接触** | 恢复任务刚度 | `K_d = 100~2000 N/m`<br>`ζ = 0.8~1.0`<br>开始力跟踪/位置跟踪混合 | 正常作业 |

#### 参数平滑过渡（**避免阶跃切换**）

> 原文：`K_d` 从 500 瞬间跳到 50 会造成二次冲击，必须用平滑过渡函数。

$$
K_d(t) = K_{start} + (K_{end} - K_{start})\cdot s\!\left(\frac{t-t_0}{T_{trans}}\right)
$$

其中 **smootherstep**（五次多项式，两端速度与加速度均为 0）：

$$
s(\tau) = 6\tau^5 - 15\tau^4 + 10\tau^3,\qquad
s(0)=0,\ s(1)=1,\ s'(0)=s'(1)=0,\ s''(0)=s''(1)=0
$$

**注意**：这和我们 `trajectory.hpp` 里的五次多项式是**同一类函数**（smootherstep 是五次多项式的特例，边界条件全零）。可以直接复用。

#### 过渡时间选择（原文）

| 过渡 | 推荐时长 | 理由 |
|---|---|---|
| Phase 1 → 2 | **瞬时**（由检测触发） | 检测到接触必须立即响应 |
| Phase 2 → 3 | **10~50 ms** | 快速降低刚度吸收冲击 |
| Phase 3 → 4 | **100~500 ms** | 缓慢恢复刚度，避免二次冲击 |

```
┌──────────────────────────────────────────────────┐
│ 接触状态机（一维 FSM）                             │
│   APPROACH → CONTACT → ABSORB → STEADY → ...     │
│                                                   │
│ 每周期：                                          │
│   1. 读力/力矩估计                                 │
│   2. 状态转移判断（阈值 + 计时）                    │
│   3. 用 s(τ) 插值 K_d / D_d                        │
│   4. 输出给阻抗控制器（C-18）                       │
└──────────────────────────────────────────────────┘
```

```cpp
enum class ContactPhase { APPROACH, ABSORB, STEADY };

// 每周期（250 Hz）
switch (phase_) {
  case APPROACH:
    K_d_ = 500.0;
    if (force_norm > f_threshold_) { phase_ = ABSORB; t_phase_ = 0; }
    break;
  case ABSORB:
    t_phase_ += dt;
    K_d_ = lerp_smootherstep(500.0, 75.0, t_phase_ / 0.03);    // 30 ms
    if (t_phase_ > 0.2) { phase_ = STEADY; t_phase_ = 0; }
    break;
  case STEADY:
    t_phase_ += dt;
    K_d_ = lerp_smootherstep(75.0, task_K_d_, t_phase_ / 0.3); // 300 ms
    break;
}
```

#### ⚠️ 我们的关键约束

**① 检测延迟**：250 Hz → 1 个周期 4 ms，**满足"< 10 ms"** ✅

**② 力感知从哪来**（我们没有 F/T 传感器）：

| 方案 | 分辨率 | 精度 | 是否可用 |
|---|---|---|---|
| **电机 τ 反馈 + Jᵀ 映射** | 0.0034~0.098 N·m | ±5~20% | ✅ 可用 |
| **动量观测器**（F06） | 依赖模型 | 延迟 ~10 ms | ⚠️ 需 SysId |
| 加装 F/T 传感器 | 0.01~0.05 N | ±1% | 需硬件 |

**阈值 2~5 N 用电机 τ 估计可能不够灵敏**（joint1 分辨率 0.098 N·m，在 0.5m 处 ≈ 0.2 N，勉强够；但精度差会被摩擦淹没）。

**建议**：先用**动量观测器**做接触检测，或用**位置误差突增**（碰撞时 q̇ 骤停）作为辅助判据。

**③ 250 Hz 下的接触刚度上限**：

```
K_e < D_d/(2Δt)  →  D=100 Ns/m 时；K_e < 12.5 kN/m
```

Phase 4 的 `K_d = 100~2000 N/m` 是**机器人侧刚度**，环境刚度才是限制。碰硬塑料（~100 kN/m）以上时 250 Hz 不够。

#### 验收标准

| 项 | 判据 |
|---|---|
| 接触检测延迟 | < 10 ms（1~2 个控制周期） |
| 冲击力峰值 | < 30 N（原文：防止零件损伤） |
| 参数切换平滑性 | `dK_d/dt` 无阶跃（可用日志检查二阶差分） |
| 稳态接触力 | 误差 < 1 N（需要好的力感知） |
| 无二次冲击 | Phase 3→4 过渡期间力峰值不超过稳态的 1.5 倍 |

#### 为什么暂缓

- 需要先有**力感知**（我们现在没有）
- 需要先有**阻抗控制器**（C-18）
- 需要先有**动力学模型**（C-16）
- 当前阶段（重力补偿）根本不涉及接触

### [ ] C-20 接触模式切换的统一状态机（自由/碰撞/粘着/滑动/分离）

- **状态**：⏸ **暂缓**——等真正需要处理接触问题时再做
- **前置**：C-16（动力学）、C-18（控制器）、**C-19（过渡策略）**、力感知能力
- **来源**：达妙教程 F02「8.6 接触模式切换的统一状态机」

#### 和 C-19 的区别（两者互补，不是重复）

| | **C-19 接触过渡策略** | **C-20 接触状态机** |
|---|---|---|
| 覆盖 | **"进入接触"的四个阶段** | **"接触期间"的状态流转** |
| 状态 | 接近 → 检测 → 吸收 → 稳定 | 自由 → 碰撞 → 粘着 ⇄ 滑动 → 分离 |
| 时间尺度 | 一次性的（几百 ms） | 持续运行（整个任务期间） |
| 解决的问题 | 首次接触的冲击 | 装配中反复的粘滑/脱离 |

**C-19 是"进门"，C-20 是"屋里的活动"。**

#### 状态转移图（原文）

```
        ┌─────────────────────────────────────────┐
        ▼                                         │
  [自由空间] ──(delta > 0)──→ [碰撞]               │
        ▲                        │                │
        │                   (v_n < v_th)          │
   (delta = 0)                   ▼                │
        │                    [粘着] ────────────────┘
        │                        │
        │                   (|f_t| > μ·f_n)
        │                        ▼
        │                    [滑动]
        │                        │
        │                   (v_t < v_th)
        │                        ▼
        │                    [粘着]（回到）
        │                        
        └───(f_n < f_th)──── [分离] ←── 粘着
```

**转移条件**：

| 转移 | 判据 | 含义 |
|---|---|---|
| 自由 → 碰撞 | `delta > 0`（逼近量/穿透） | 首次接触 |
| 碰撞 → 粘着 | `v_n < v_th`（法向速度降到阈值以下） | 冲击衰减完 |
| 粘着 → 滑动 | `\|f_t\| > μ·f_n`（切向力超摩擦锥） | 打滑 |
| 滑动 → 粘着 | `v_t < v_th`（切向速度降到阈值以下） | 重新咬合 |
| 粘着 → 分离 | `f_n < f_th`（法向力掉到阈值以下） | 离开表面 |
| 分离 → 自由 | `delta = 0` | 完全脱离 |

#### 每种状态的阻抗参数（原文表格）

| 状态 | `K_d` (N/m) | `D_d` 策略 | `M_d` 策略 | 控制重点 |
|---|---|---|---|---|
| **自由空间** | 500~2000 | 临界阻尼 | Λ | 位置跟踪精度 |
| **碰撞** | **50~100** | **过阻尼 ζ=1.5** | Λ | 冲击吸收 |
| **粘着** | 100~500 | 临界阻尼 | Λ | **法向力跟踪** |
| **滑动** | 100~500 | 临界阻尼 | Λ | **切向速度 + 法向力** |
| **分离** | 500~2000 | 临界阻尼 | Λ | 快速回位 |

**关键观察**：
- **碰撞态最软**（K_d 50~100）——吸收冲击
- **粘着/滑动用中刚度**（100~500）——力跟踪需要适度刚度
- **自由/分离用高刚度**（500~2000）——位置跟踪
- `M_d` 全是 Λ（操作空间惯量）——保持动力学一致

#### 实现要点

```
① 状态机 + 迟滞（hysteresis）
   每个阈值必须有 ±10~20% 的死区，否则会在边界反复抖动
   例：v_th = 5 mm/s，则 进入粘着 at < 4 mm/s，退出 at > 6 mm/s

② 参数切换用 C-19 的 smootherstep
   s(τ) = 6τ⁵ − 15τ⁴ + 10τ³
   不能直接赋值 K_d = new_value

③ 力分解需要接触坐标系
   f_n = f · n̂（法向）
   f_t = f − f_n·n̂（切向）
   n̂ 从哪来？
     · 已知工件表面（CAD/标定）
     · 或用力矩/几何估计表面法向

④ 状态输出不只是参数，还有任务目标
   · 粘着：法向力跟踪（力闭环）
   · 滑动：切向速度控制（恒速滑动）+ 法向力保持
   → 控制律也要跟着切换
```

#### ⚠️ 我们的关键约束

**① 无力传感器 → f_n / f_t 分解做不到**

```
需要：f_n（法向力）、f_t（切向力）、μ（摩擦系数）
没有 F/T 传感器时只能：
   · 用电机 τ + Jᵀ 估算总 wrench
   · 但精度 ±5~20%，且分不清法向/切向（需要接触面法向）
```

**② 接触坐标系未知**

我们的机械臂没有"工件表面"的概念。要做装配，必须先知道：
- 孔/轴的方向
- 工件的位姿（视觉或标定）

**③ 250 Hz 下的状态切换抖动**

状态机在 250 Hz 下运行，但力信号有噪声 → 可能高频抖动
→ **必须加滞回 + 连续计数（连续 N 个周期满足才切换）**

**④ 阈值经验值**（原文给的，可作初值）

```
v_th  = 5 mm/s      法向/切向速度阈值
f_th  = 2~5 N       接触力阈值
mu    = 0.2~0.8     摩擦系数（取决于材料）
delta = 0.1~1 mm    穿透/逼近量阈值
```

#### 四项检查 + 我们踩到的两个坑

| # | 检查 | 教程写法 | 我们的修正 |
|---|---|---|---|
| ① | 正定性 | `eig(K_d) > 0` | ✅ 照用 |
| ② | 阻尼比 | `ζ ≥ 0.7` | ⚠️ 改**区间** `[0.7, 2.0]`——否则会挡住 C-19 Phase 3 的 **ζ=1.5 过阻尼** |
| ③ | 刚度上界 | `K_d < K_s` | ❌ **有单位问题**——6×6 矩阵混了 N/m 和 Nm/rad，整体特征值不可比。**必须用特征长度归一化** |
| ④ | 离散稳定性 | 只有注释，**没实现** | ❌ **必须补**——这是唯一会导致"实际接触振荡"的检查 |

#### ⚠️ 坑 1：`K_d < K_s` 的单位混用

我们用 kp=70 换算出的实际笛卡尔刚度：

```
K_s 对角 = [6020, 18351, 7667,    16.5,  43.0,  23.3]
            └──── N/m（平移）───┘  └── Nm/rad（旋转）──┘

直接对 6×6 求特征值 = [7.7, 8.9, 51.3, 396, 734, 30922]   ← 无物理意义！
```

**后果**：`K_d = 500 N/m`（平移，完全合理）会被判成 "500 > 7.7 → 超出 K_s" **误报**。

**修正：用特征长度 L 归一化**

```python
L = 0.3                                   # 特征力臂（0.2~0.5 m）
S = np.diag([1,1,1, 1/L,1/L,1/L])         # Nm/rad → 等效 N/m
K_hat = S @ K_s @ S                       # 全部 N/m
# → 特征值 [81, 97, 403, 443, 1009, 30926] N/m   ← 可比较了
```

#### ⚠️ 坑 2：Colgate-Schenkel 离散稳定性

$$
K_e < \frac{D_d}{2\Delta t}
$$

**我们 250 Hz（Δt=4 ms）的实际能力**：

| `D_d` | 可稳定接触的环境刚度 |
|---|---|
| 50 Ns/m | **6.2 kN/m** |
| 100 Ns/m | **12.5 kN/m** |
| 200 Ns/m | 25 kN/m |
| 500 Ns/m | 62.5 kN/m |

**参考**：泡沫 ~1k、橡胶 ~10k、硬塑料 ~100k、金属 ~1e6 kN/m

> **结论：250 Hz 只能稳定接触软塑料以下。**
> 要碰硬塑料/金属，必须上 1 kHz（MCU 方案的价值再次体现）。

#### 完整检查器（单位安全版）

```python
def check_impedance(K_d, D_d, M_d, K_s, T_s, K_e_range, L=0.3):
    # ① 正定性
    for name, M in [("K_d", K_d), ("D_d", D_d), ("M_d", M_d)]:
        ev = np.linalg.eigvalsh(M)
        assert np.all(ev > 0), f"{name} not PD: {ev}"

    # ② 阻尼比（区间）
    zeta = np.diag(D_d) / (2 * np.sqrt(np.diag(K_d) * np.diag(M_d)))
    assert np.all((zeta >= 0.7) & (zeta <= 2.0)), f"zeta={zeta}"

    # ③ 刚度上界（单位归一化）
    S = np.diag([1, 1, 1, 1/L, 1/L, 1/L])
    ev_s = np.linalg.eigvalsh(S @ K_s @ S)
    ev_d = np.linalg.eigvalsh(S @ K_d @ S)
    assert np.all(ev_d < ev_s * 0.9), \
        f"K_d 逼近 K_s: {ev_d.max():.0f} vs {ev_s.min():.0f}"

    # ④ 离散稳定性（留 20% 裕度）
    K_e_max = max(K_e_range)
    for i in range(6):
        lim = D_d[i, i] / (2 * T_s)
        assert K_e_max < lim * 0.8, \
            f"axis {i}: K_e={K_e_max/1e3:.1f}k 超过上限 {lim/1e3:.1f}k"
```

#### 五项建议补充的检查

| # | 检查 | 为什么 |
|---|---|---|
| 1 | **`K_d` 下限** | 太小顶不过摩擦死区（我们实测 0.006 rad） |
| 2 | **`M_d` 偏离 Λ 的程度** | `M_d ≠ Λ` 需要精确动力学补偿，偏差大易失稳 |
| 3 | **`D_d` 对力噪声的放大** | 高 `D_d` 把力噪声放大成指令抖动 |
| 4 | **用实测 `Δt` 而非标称** | 我们实测 244~250 Hz 波动，按 244 Hz 算才安全 |
| 5 | **力矩饱和** | `K_d·Δx_max + D_d·v_max` 应 < 关节 `tMax` |

#### ④ 两种「梯度」完全不同（核心判断）

| | 位姿梯度（**已用**） | 碰撞梯度（**未用**） |
|---|---|---|
| 函数 | `e(q) = log6(T_current(q)⁻¹ T_target)` | `d(q) = min‖p_A(q) − p_B(q)‖` |
| 维度 | **6**（3 位置 + 3 姿态） | **1**（标量距离） |
| 梯度 | `∂e/∂q = J_task`（6×n） | `∂d/∂q = (J_pB − J_pA)ᵀ n̂`（n×1） |
| 来源 | 末端帧雅可比 | 两个几何体的**最近点对** |
| 有效性 | 处处可导 | **只对 d > 0 有效**（穿透时无定义） |

我们的 `kinematics.hpp::solveIK()` 只迭代 `e(q)`，代码里没有任何碰撞项；
关节限位是**硬钳制**（`q = clamp(q, lo, hi)`），不是约束优化。

#### ⑤ 什么时候需要碰撞梯度（**判断表**）

| 场景 | 需要？ | 原因 |
|---|---|---|
| **6-DOF 定位 IK** | ❌ | 冗余度 = 6−6 = **0**，没有零空间可避障 |
| **多解 + 事后筛选** | ❌ | 已有 `solveIKMultiSeed` 返回 ≤8 个解，调用者选不撞的 |
| **MoveIt 规划（布尔碰撞）** | ❌ | `computeCollisions` 0.018 ms 足够 |
| 7-DOF 冗余臂 | ✅ | 零空间避障：`dq = J⁺e + (I−J⁺J)k∇d` |
| **CHOMP / STOMP 轨迹优化** | ✅ **必须** | 优化目标含碰撞代价项，梯度下降靠它 |
| **MPC / 预测控制** | ✅ **必须** | 要预测未来 N 步距离 |
| 碰撞约束 IK（QP） | ✅ | `min‖J dq − e‖² s.t. ∇dᵀdq ≥ margin − d` |
| 贴边接近 / 接触前减速 | ✅ | 用距离做减速曲线 |

> **6-DOF 的关键结论**：末端位姿一固定，臂形就确定（除多解分支），
> 提高 d(q) 必然增大 e(q) —— 两者在 6-DOF 下**必然打架**。
> 所以「多解 + 筛选」比「带碰撞梯度的 IK」更合适。

#### ⑥ 触发条件（满足任一条再动手）

1. 上**轨迹优化**（CHOMP / STOMP / 自己写的）
2. 上 **MPC**
3. 需要**贴边接近**或力控接触前减速
4. 规划耗时 **> 100 ms**
5. 换 **7-DOF** 冗余臂

#### ⑦ 实施方向（真要做时，按推荐度）

| 方案 | 距离计算 | 梯度 | 精度 | 工作量 |
|---|---|---|---|---|
| **① 胶囊 / 球体包络** ⭐ | **闭式（μs 级）** | **解析连续** | 中（膨胀可控） | 中（每 link 2~4 个胶囊） |
| ② 凸包分解（V-HACD） | 快 | 连续 | 高 | 大 |
| ③ 凸包 | 0.753 ms | 有跳变 | 低（4.9% 误报） | **小** |
| ④ 原始 mesh（现状） | 1.875 ms | 有跳变 | 最高 | 无需 |

**推荐 ① 胶囊** —— 距离是"两线段最短距离"的闭式解，梯度解析可导，无最近点跳变。

#### ⑧ 中间方案（**不改几何也能做**）

用 `computeDistances` + 安全边距代替 `computeCollisions`：

```python
pin.computeDistances(m, d, gm, gd, q)
free = all(r.min_distance > SAFETY_MARGIN for r in gd.distanceResults)
```

好处：
- 不用重建几何
- 保证 **d > margin > 0** → 梯度**永远有定义**（绕开"穿透无梯度"）
- 可以做"软避障"（离得越近惩罚越大）

#### ⑨ 教程代码的 4 个坑（已实测确认）

1. **`addAllCollisionPairs()` + `removeCollisionPairs()` 必须成对**
   只调前者 → 6 对相邻件永远 `d = 0` → 任何位形都报碰撞
2. **`getJointJacobian` 必须 `LOCAL_WORLD_ALIGNED`**
   用 `LOCAL` 会错几十厘米（因为 `r_A = p1 − oMi[joint].translation()` 是世界系向量）
3. **穿透时无梯度**：`d ≤ 1e-10` 时必须抛异常或退回 EPA/接触法向
4. **Python 绑定 API 不同**：C++ 是 `getJointJacobian(m,d,jid,frame,J_out)`（输出参数），
   Python 是 `J = pin.getJointJacobian(m,d,jid,frame)`（返回值）

#### ⑩ 梯度公式正确性（已验证 ✅）

用有限差分校验 `∂d/∂q = (J_pB − J_pA)ᵀn̂`：

```
pair              距离      ‖grad‖    FD 相对误差
base_link<->link2  13.2 mm   0.004     4.5e-10
base_link<->link2  13.5 mm   0.006     8.9e-10
base_link<->link4 115.1 mm   0.234     1.5e-10
```

→ **公式正确**（精度 1e-10），只在"最近点对不变"的邻域内成立

#### ⑪ 验收标准（真做时）

- `computeDistances` **< 50 μs**（4 对）
- 凸包/胶囊误报率 **< 1%**
- 梯度 FD 误差 **< 1e-6**
- 工作空间损失 **< 2%**

#### ⑫ 文件规划

```
hw_arm_algorithms/include/hw_arm_algorithms/collision.hpp
├── loadCollisionGeometry(model, urdf)      // mesh 或 capsule
├── computeDistance(q, pair)                 // 标量
└── computeDistanceGradient(q, pair)         // n×1（d > margin 时有效）
```

或者：**视觉用 mesh、碰撞用 capsule**（MuJoCo 原生支持 capsule，Pinocchio 从 URDF 也能读）

- **依赖**：相机 + 标定板 + C-01 完成 + C-17（要用 IK 去够位姿）
- **代码基础**：已有一版 `hand_eye_calibrate()`（封 OpenCV `calibrateHandEye`，5 种方法对比）

#### 坐标系约定（已用合成真值验证 ✅）

| 喂给 OpenCV 的量 | 我们的来源 | 注意 |
|---|---|---|
| `R_gripper2base` / `t_gripper2base` | `pd.oMf[pm.getFrameId("tool0")]`，即 **`T_base_tool0`** | 不是 `T_tool0_base` |

实测（2026-11-14）：构造已知 `X_true`，反推 `Y_i` 再标定

```
X_true t = [0.02 -0.01 0.15]
X_est  t = [0.02 -0.01 0.15]      平移误差 0.0000 mm  旋转误差 0.0000 deg
Tsai / Park / Horaud / Daniilidis / Andreff  五种方法全部 0.0000 mm
```

→ **约定正确，可以放心用。**

#### ⚠️ 必须补的三个保护（否则会骗自己）

| # | 问题 | 实测现象 | 修法 |
|---|---|---|---|
| 1 | **旋转退化时静默返回 NaN** | 15 组数据只绕单轴转 → `X_est t = [nan nan nan]`，OpenCV **不报错** | ① 旋转轴多样性检查（≥2 独立轴、每轴 ≥30°、轴矩阵 σ₃/σ₁ > 0.15）② 结果 `np.isfinite` 检查 |
| 2 | **`AX=XB` 残差不是标定精度** | 该残差**恒为 ~4 mm，不随样本数下降** | 改用**留一交叉验证（LOO）** |
| 3 | 只验平移不验旋转 | 旋转错了平移可能碰巧接近 | 同时比较 `AX` 与 `XB` 的旋转差 |

#### 验证指标对比（机器人噪声 0.5mm/0.05°，相机 1mm/0.2°）

| n | 真误差 (mm) | `AX=XB` 残差 | P 散布 (mm) | **LOO (mm)** |
|---|---|---|---|---|
| 6 | 2.35 | 4.24 | 1.08 | 5.32 |
| 10 | 1.17 | 3.39 | 1.55 | 3.49 |
| 15 | 2.80 | 3.93 | 1.02 | 3.35 |
| 20 | 1.50 | 4.25 | 0.90 | 2.75 |
| 30 | 0.95 | 3.87 | 0.99 | 2.90 |

→ **LOO 随样本数收敛到 ~3 mm，`AX=XB` 残差永远卡在 ~4 mm**。
   用 `AX=XB` 当指标会得出"加了数据也不变好"的错误结论。

#### 数据采集要求（成败主要在这里）

| 项 | 要求 | 原因 |
|---|---|---|
| 组数 | **15~25 组** | LOO 在 20 组后进入平台期 |
| 旋转 | 每轴 **≥30°**，至少 **2 个独立轴** | 单轴 → 直接 NaN |
| 平移 | 覆盖实际工作空间 | 平移量决定 `t` 的可分性 |
| 相机距离 | 覆盖最近/最远工作距离 | 避免外推 |
| 靶标倾角 | ±30° 都要有 | 避免 PnP 平面退化 |

#### 方法选择

- **默认 Daniilidis**：SVD 分解，对旋转噪声最鲁棒
- `Park`：精度接近，更快
- `Tsai`：老方法，会过滤小于 5° 的旋转轴，样本少时容易退化

#### 验收标准

- **LOO 平均误差 < 5 mm**（相机装腕部、工作距离 0.3~0.8 m 时应达 2~3 mm）
- 旋转误差 **< 0.5°**
- 实机复验：回到固定靶标测 10 个不同位姿，靶标在 base 下的位置散布 < 5 mm
