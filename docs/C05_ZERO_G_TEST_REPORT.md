## 3. 测试数据

### 3.1 第一轮验证 —— 发现"方法不匹配"

**6 个位形，不抖动：**

```
整体 rms 0.600   每轴 [0.455, 1.111, 0.753, 0.168, 0.302, 0.190]
```

**判断：不能用它判模型不合格。** 因为辨识时是"抖动 3 次再平均"，验证时没抖。

```
若静摩擦噪声 σ≈0.55、模型误差 0.184
→ 合成 sqrt(0.55² + 0.184²) = 0.580
实测 0.600  ← 量级完全吻合
```

**三条独立证据支持"是摩擦不是模型错"：**

1. **joint1 重力分量恒为 0**（竖直轴），但实测 τ1 在 [−0.62, +0.41] 跳，标准差 0.35
2. **残差随位形变号**：joint2 = [+0.48, +1.69, −0.49, +0.71, −0.89, +1.66]
3. 同一批位形，抖过的版本是 0.184

### 3.2 第二轮验证 —— 加抖动

```
整体 rms 0.600 → 0.415
每轴 [0.455→0.052, 1.111→0.746, 0.753→0.625, 0.168→0.145, 0.302→0.223, 0.190→0.101]
      ↑ joint1 降 8.8 倍 —— 抖动确实消掉了摩擦
```

### 3.3 第三轮验证 —— 修掉误判后的最终数据

```
整体 rms 0.420
每轴 rms  [0.109, 0.738, 0.652, 0.147, 0.216, 0.100]
每轴 |max|[0.199, 1.265, 0.925, 0.234, 0.397, 0.169]

joint2 残差 [-0.03, +1.12, -0.19, +0.21, -0.57, +1.27]  均值 +0.30  变号 5/5
joint3 残差 [+0.09, -0.76, -0.52, -0.31, -0.92, -0.87]  均值 -0.55  变号 1/5
```

**结构判读：**

| 轴 | 特征 | 结论 |
|---|---|---|
| joint2 | 三正三负，随机 | **噪声**（静摩擦残余） |
| joint3 | 五个负一个近零 | **系统性高估 0.55 N·m** |

### 3.4 近零位探针 —— 关键数据

**手工构造 q2/q3 = 8~35° 的位形（辨识从没覆盖过的区域）：**

```

joint3 残差 [-4.61, -0.85, -3.14, -0.86, -0.49, -0.85]
             ↑            ↑
        这两个 −4.6/−3.1 应该是还被结构托着
        其余四个 ≈ −0.76 是自由位形
```

**→ 靠近零位，joint3 的高估从 0.55 放大到 **0.76~0.86**。**

**探针位形已存档：** [near_zero_probe.yaml](algo/data/near_zero_probe.yaml)

## 4. 三个重要发现

### 4.1 🔍 发现 1：USB-CAN 在 250 Hz 已饱和

```
指令帧  6 × 250 Hz = 1500 fps
状态帧  6 × 250 Hz = 1500 fps
刷新查询 2 × 250 Hz =  500 fps
────────────────────────────
合计                  **3500 fps**
实测 gs_usb 可持续约 3000 fps  → **117%**
```

**这是**一直存在**的硬件瓶颈，不是重力补偿引入的**（最早的 bringup 日志里就有 `Write time 4215 us`）。

**已修：`update_rate` 默认改 125，并可用 launch 参数覆盖（用命令行 `-p` 覆盖，优先级最高）。**

### 4.2 🔍 发现 2：实际 kp 只有配置值的 **45%**

**从"实测力矩 / 位置误差"反推：**

| 位形 | τ_meas | kp·e（用配置 70 算） | 比值 |
|---|---|---|---|
| #1 | +4.02 | +8.92 | 0.45 |
| #2 | +5.29 | +12.10 | 0.44 |
| #3 | +4.72 | +8.47 | 0.56 |
| #4 | +4.58 | +10.36 | 0.44 |
| #5 | +1.71 | +4.84 | 0.35 |
| #6 | +5.35 | +11.54 | 0.46 |

**平均 kp_eff = 31.5（配置 70）→ 45%**

**根因：**

```
库里编码：kp_uint = double_to_uint(kp, 0, 500, 12)     // 发 70 → raw 573
实测 573/4095 × Kp_max = 31.5  ⇒  **电机侧 Kp_max ≈ 225，不是 500**
```

**验证（用 kp_eff=31.5 重算下垂）：**

| 重力矩 | kp=70 应下垂 | kp=31 应下垂 | **实测** |
|---|---|---|---|
| 2.4 N·m | 2.0° | 4.4° | **4.4°** ✓ |
| 5.2 N·m | 4.3° | 9.6° | **9.6°** ✓ |

**⚠️ 不影响辨识结果**（辨识用实测 q 和实测 τ，与 kp 无关），**但影响所有"下垂量"的预期。**

## 5. 为什么做完辨识还往上飘

### 5.1 先排除算法

| 实现 | 同一 q 的输出（N·m） |
|---|---|
| C++ 插件 `computeGravityFromParamsAndOffset` | `[-0.150, 2.421, 6.056, -0.141, 0.094, 0.040]` |
| Python `Y(q)·θ̂ + offsets` | `[-0.151, 2.413, 6.057, -0.140, 0.092, 0.040]` |
| **最大差** | **0.008 N·m** |

**→ 算法实现正确，刚体重力模型 `g = Y(q)·θ` 在数学上是精确的。**

### 5.2 三个原因，按证据强度

| # | 原因 | 证据 | 贡献 |
|---|---|---|---|
| **①** | **恒定力矩偏置漂移** | 同一位形两次测量差 0.6~1.0 N·m | **约 0.6** |
| ② | 外推到零位附近 | 残差从 −0.55 放大到 −0.76 | 约 0.2 |
| ③ | 摩擦/迟滞 | 抖动后已降到 0.1~0.2 | 小 |

**已排除：**

- ❌ 算法实现错误（两套独立实现差 0.008）
- ❌ 刚体模型结构错误
- ❌ 关节零位偏移（残差斜率只有 −0.008 N·m/°，而零位偏移应有 ±0.09，**小一个数量级**）

### 5.3 偏置是什么

```
tau_meas = Y(q)·θ  +  offsets
                       ↑
              所有"与位形无关"的力矩
```

**能产生恒定力矩的机制：**

| 机制 | 量级核对 | 判断 |
|---|---|---|
| **电流检测零点误差**（温漂） | 0.8 N·m ≈ 0.8 A 偏置（12 A 量程的 6.7%） | 可能 |
| **线束张力** | 5 N × 0.16 m = **0.8 N·m** | ✅ **量级正好，且能解释"只有 joint3 变"** |
| 减速器预紧/背隙 | 应进 friction 项，实测只有 0.004~0.038 | ❌ 排除 |
| 末端质量变化 | 需 0.54 kg | ❌ 不可能 |

### 5.4 ⚠️ 数据分不清"真实力"还是"测量误差"

```
真实多一个 0.8 N·m  →  tau_meas 高 0.8
传感器少读 0.8 N·m  →  tau_meas 也高 0.8
        ↓
数据上完全等价
```

**但对零重力的影响相反：**

| 情况 | 补偿它 |
|---|---|
| 真实多了一个力（线束） | ✅ 正确 |
| 传感器读偏 | ❌ 错上加错，越补越飘 |

### 5.5 根本矛盾：零重力对残差零容忍

```
位置控制（kp=70）：
    残差 0.8 N·m → 静态偏差 0.8/70 = 0.65°
    → 完全可用

零重力（kp=0）：
    残差 0.8 N·m → 漂移 0.8/1.5 = **29 °/s**
    → 肉眼可见"自己往上飘"
```

**同样的 0.8 N·m，位置控制下是 0.65° 误差，零重力下是每秒 29°。**

## 6. 已实现但未提交：运行时零重力服务

### 6.1 为什么要它

```
零重力启动点默认在 q≈0（return_to_zero）
        ↓
但零位是**机械结构托住**的，那儿测不到真实重力
        ↓
模型在 q=0 给出 joint3 = 6.06 N·m（**从未验证过**）
        ↓
一离开结构支撑，多出来的力就把机械臂往上推
        ↓
**正确做法：先用位置控制走到自由位形，再切零重力**
```

### 6.2 实现

**服务：`/hw_arm_hardware_interface/set_zero_gravity`（`std_srvs/SetBool`）**

```bash
ros2 service call /hw_arm_hardware_interface/set_zero_gravity \
    std_srvs/srv/SetBool "{data: true}"     # 进入零重力
ros2 service call /hw_arm_hardware_interface/set_zero_gravity \
    std_srvs/srv/SetBool "{data: false}"    # 退出
```

**实测结果：**

```
std_srvs.srv.SetBool_Response(success=True, message='zero-gravity ON')
日志：★ 进入零重力（kp → 0，只靠 tau_ff 支撑）
```

**切换是瞬间的（不做渐变）**：位置控制下稳态误差 `e=(g−tau_ff)/kp`，若 `tau_ff≈g` 则 `e≈0`，切 kp→0 时机械臂几乎不动（误差 0.65° 量级）。

## 9. 下一步（**需你在场**）

### 第 0 步：评估损坏（优先）

- 哪些部件受影响
- 是否还能安全上电（**先只上电不使能**，看有没有异常）
- 有没有异响、卡滞、松动、结构件变形

### 第 1 步：修掉偏置漂移 —— **自动偏置校准**（推荐）

**核心思路：不查明原因，直接测出净差额。**

```
位置控制 → 到自由位形 → 稳态
        ↓
读 effort（此时 = 真实重力 + 传感器偏置）
        ↓
trim = tau_meas − g_pred      自动算，clamp ±3 N·m
        ↓
零重力时 tau_ff = g_pred + trim = **位置控制下的实际出力**
        ↓
**不管偏置是真实力还是测量误差，效果都对**
```

**⚠️ 前提：必须在**自由**位形做（不能是结构托住的零位）。**

### 第 2 步：把辨识范围扩到工作区

**补采 q2/q3 = 8~35° 这片自由位形，重拟合。** 能修掉外推那部分（约 0.2）。

### 第 3 步：慢速积分补偿（真正的零重力做法）

```
检测到某轴持续低速漂移 → 对 tau_ff 做慢积分把它拉回
```

**商业示教系统都这么做，但需要小心调参数否则会振荡。**
