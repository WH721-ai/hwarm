# 加视觉、加触觉：框架会怎么变

> 结论先行：
> **视觉加的是"感知层"，不改变控制环；触觉改的是"控制律"，并且必须待在快环里，不能进策略环。**
> 两者共同的新问题是：**时间同步 + 置信度（协方差）**，而不是"多接一个传感器"。

---

## 0. 一句话版本

| 加什么 | 框架变化 | 变的是哪一层 | 工期 |
|---|---|---|---|
| 相机 | 多一个**感知层**（相机→检测→位姿→TF→场景），MoveIt2 的 PlanningScene 从静态变动态 | 决策层之上 + 规划层的输入 | +1–2 周 |
| 触觉/力 | **控制层从位置控制改成阻抗/力位混合**，抓取变成事件状态机 | 控制层 + 硬件层 | +1–2 周 |
| 两个都加 | 上面两条叠加，再加**统一参考包**（μ, Σ, frame, t, validity）与时钟同步 | 全局 | +1 周联调 |

---

## 1. 加视觉：多一个感知层

### 1.1 新的数据流

```
相机 30 Hz ──▶ 检测/分割 5–30 Hz ──▶ 6D 位姿估计 ──▶ TF(手眼) ──▶ 世界坐标 pose
                                                                  │
                                    ┌─────────────────────────────┤
                                    ▼                             ▼
                        PlanningScene（物体/点云）        BT 的感知条件节点
                                    │                             │
                                    ▼                             ▼
                              MoveIt2 规划                  "抓哪个/能不能抓"
```

### 1.2 频率台阶（教程给出的骨架，直接用）

| 环节 | 频率 |
|---|---|
| VLM / 语义可供性 | 1–10 Hz |
| 任务策略 | 10–50 Hz |
| 物体检测 / 分割 | 5–30 Hz |
| 物体跟踪 | 10–60 Hz |
| 建图 / SDF / 点云 | 5–30 Hz |
| 状态估计 | 100–400 Hz |
| MPC | 20–100 Hz |
| WBC / 控制 | 500–1000 Hz |
| 硬件 / MCU | 1 kHz+ |

### 1.3 三个必须改的接口

**① 参考包必须带协方差和有效期，不能只传 pose**

```yaml
reference:
  mu:        [x, y, z, qx, qy, qz, qw]
  sigma:     [σx, σy, σz, σax, σay, σaz]   # 6x6 对角或全阵
  frame:     "camera_color_optical_frame"
  stamp:     1234.567
  validity:  100 ms        # 30 Hz 检测 → 100 ms 有效期
  priority:  1
```

**教程的硬结论**：只传 pose 均值是反模式。**协方差是控制输入**：
- 权重调度 `Q(Σ) = Q_max / (1 + α·tr(Σ))`
- 约束收紧 `d ≥ d₀ + k·√λ_max(Σ)`（95% 取 k=1.64，99% 取 2.33）
- **pose 抖动不是控制问题**：正确反应是**降末端刚度 + 主动观察**，不是提高刚度去追——追抖动的后果是接触力突变、抓取中脱手

**② 时间同步 < 1 ms**

相机时间戳要和关节状态对齐，否则末端轨迹出现锯齿。ROS 2 用 `message_filters` + `tf2` 的 `TimePointZero` 兜底，但**工程上必须显式做时钟同步**（PTP 或同一台机器的 `CLOCK_MONOTONIC`）。

**③ 坐标系**

教程原话：**坐标系错是最高频集成 bug**。手眼标定要单独出 `camera → tool0`（eye-in-hand）或 `camera → base`（eye-to-hand）的静态 TF，并在 URDF 里显式写死。

### 1.4 视觉解决不了 0.1 mm —— 这是最重要的一条

| 环节 | 典型精度 |
|---|---|
| 电机编码器 / 关节 | **0.01 mm 级** |
| FK / IK（我们生成的代码） | **µm 级** |
| **手眼标定** | **0.5–2 mm** ← 主要瓶颈 |
| RGB-D 6D 位姿估计 | 2–20 mm |
| VLM / 语义可供性 | 只答"抓哪"，不答"抓多准" |

**所以：视觉只能把目标带到 ±1–2 mm，剩下两个数量级必须靠"粗到细"策略**：

```
视觉粗定位（±1–2 mm）
   → 视觉伺服（IBVS/PBVS，30–100 Hz，闭环修正到 ±0.3 mm）
   → 接触搜索（力/触觉，螺旋/斜坡搜索，到 ±0.05 mm）
```

**千万不要**在 MoveIt2 里把视觉位姿当精确目标直接规划到 0.1 mm——它到不了，而且规划器会以为能到。

### 1.5 MoveIt2 侧的具体改动

| 项 | 改动 |
|---|---|
| PlanningScene | 增加物体 `CollisionObject`（检测到 → add，抓取 → attach，放下 → detach，移走 → remove） |
| 自碰撞矩阵 ACM | 物体 attach 后：跳过 `object ↔ touch_links`（手指），但**仍检查** `object ↔ 环境` 与 `object ↔ 机身` |
| 避障 | 可选：深度点云 → Octomap，让规划器看到"未建模的障碍" |
| 规划器 | 仍是 RRT-Connect；**但目标点来自感知，要做"目标不可达"的预检**（先过 IK 多解筛选，再进规划器，否则白跑 5 s） |
| 时间参数化 | 仍是 Ruckig（jerk 限制），不变 |

**坑**：`addCollisionObjects()` 走的是 diff，返回 ≠ 已生效；"更新场景后立刻规划"要用服务式 `applyCollisionObject()`。

## 2. 加触觉：控制律要改，而且必须留在快环

### 2.1 触觉有两条通道，别混

| 通道 | 内容 | 频率 | 去哪 |
|---|---|---|---|
| **离散事件** | 接触建立 / 滑移 / 脱手 / 卡死 | 事件驱动 | 抓取状态机、BT |
| **连续力值** | 法向力、切向力、接触位置 | 50–1000 Hz | 阻抗控制、夹持力闭环 |

### 2.2 决定性的一条：触觉不可能进策略环

教程的量化结论：

> 策略一次决策 **20–160 ms**，而力学事件发生在 **1–10 ms**。
> 所以 **触觉/滑移检测不可能进 VLA 闭环，只能进 MCU / ros2_control 的快环。**

这一条直接决定了框架怎么切：

```
触觉/力传感器 ──┬──▶ PC：触觉图像处理（GelSight/DIGIT，30–100 Hz）→ 接触状态、目标夹持力
                └──▶ MCU：力/电流快环（1 kHz）→ 夹持力闭环、滑移保护
```

**Vision-based tactile（GelSight、DIGIT、9DTact）**：需要图像处理，只能放 PC，30–100 Hz，**到不了 1 kHz**。
**力/力矩传感器、电流估计**：可以放 MCU，1 kHz，用于滑移兜底。

### 2.3 控制层要改什么

| 原架构（纯位置） | 加触觉/力后 |
|---|---|
| JTC 位置控制 | **阻抗控制**（推荐）或 力位混合 |
| 夹爪：位置/行程 | 夹爪：**力闭环**（目标夹持力 + 滑移检测加力） |
| 抓取 = 一个动作 | 抓取 = **状态机**：接近 → 接触 → 加载 → 保持 → 释放 |
| 无 F/T | F/T 传感器进 `ros2_control` 的 state interface（前缀 `ft_sensor.name`） |

**力控律选择（教程 F03 的硬结论）**：

| 控制律 | 稳定性 | 适用 |
|---|---|---|
| **阻抗控制** | 靠无源性，对**任何**环境刚度 K_e 稳定 | **推荐默认** |
| 力 PI | 稳定域依赖 K_e，**钢面/硬表面会失稳** | 只用于已知柔性环境 |
| 导纳控制 | 需满足 `K_e < D_d/(2Δt)` 才不发散 | 力传感 + 位置接口的场景 |

**注意**：导纳的稳定性判据依赖控制周期 `Δt`——这就是为什么 1 kHz 伺服有意义，但导纳带宽仍只有 5–12 Hz。

### 2.4 触觉接进来后的完整事件流

```
① BT: "抓取红色方块"
② MoveIt2: 规划到预抓取位姿（视觉给，±2mm）
③ 控制层: 阻抗靠近（低刚度，K=200 N/m）
④ 触觉事件: contact=true（法向力 > 0.5 N）→ 停止下压，切"加载"
⑤ 夹爪力闭环: 目标 3 N，滑移检测（切向力突变 / 触觉图像位移）→ 加力到 5 N
⑥ 事件: slip=false, force_stable → 抬升
⑦ MCU 全程 1 kHz 兜底：力超限 → 零力矩；断链 → 保持
```

### 2.5 时间同步变成三路

| 传感器 | 频率 | 同步要求 |
|---|---|---|
| 相机 | 30 Hz | < 1 ms（与关节状态） |
| 触觉 | 30–100 Hz | < 2 ms |
| F/T | 1 kHz | 与 MCU 同源时钟 |

三路一起时，**统一时间基准**（同一台 PC 的 `CLOCK_MONOTONIC`，MCU 用 `DWT->CYCCNT` 换算）是必须的，否则"接触事件"和"关节位置"对不上，阻抗控制会算错接触点。

## 3. 加完之后的完整架构

```
┌─ 感知层（新增）  非实时 ──────────────────────────────────────────┐
│ 相机 30 Hz ─▶ 检测 5–30 ─▶ 6D pose(μ,Σ,t,frame) ─▶ TF ─▶ 场景     │
│ 触觉 30–100 Hz ─▶ 接触状态 / 滑移事件                              │
│ F/T 1 kHz（经 MCU）─▶ 力值                                        │
│ 输出：带置信度与有效期的参考包 + 事件                              │
└──────────────────────────┬───────────────────────────────────────┘
                           ▼
┌─ 决策层 BT  10–20 Hz ────────────────────────────────────────────┐
│ 感知条件节点（"看到目标了吗"）/ 抓取技能序列 / 失败恢复            │
└──────────────────────────┬───────────────────────────────────────┘
                           ▼
┌─ 规划层 MoveIt2  事件驱动 ────────────────────────────────────────┐
│ PlanningScene（URDF + 物体 + 可选点云）/ IK 插件 / RRT / Ruckig    │
└──────────────────────────┬───────────────────────────────────────┘
                           ▼
┌─ 控制层 ros2_control  500–1000 Hz ────────────────────────────────┐
│ JTC（位置）或 阻抗控制器（力控）/ 夹爪力闭环 / 导纳（如需）         │
└──────────────────────────┬───────────────────────────────────────┘
                           ▼
┌─ 硬件层  1 kHz ───────────────────────────────────────────────────┐
│ PC → MCU 设定点（含 Kp/Kd/τ_ff）→ MCU 插补 + g(q) + 限幅          │
│ → CANFD → 6 台 MIT 电机；触觉事件 → 夹持力调整                     │
└───────────────────────────────────────────────────────────────────┘
```

## 4. 建议的推进顺序（别一次全上）

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 纯位置控制跑通（现在这条路） | 关节轨迹跟得上，无飞车 |
| P2 | 加相机：手眼标定 + 检测 + PlanningScene | 抓取成功率 > 80%，位姿误差 < 5 mm |
| P3 | 加视觉伺服 / 接触搜索 | 末端定位 < 0.5 mm |
| P4 | 加 F/T + 阻抗控制 | 碰撞不超力，柔顺接触稳定 |
| P5 | 加触觉 + 滑移检测 | 抓取力自适应，滑移 < 1 mm |

**理由**：视觉和触觉都会引入新的**坐标系与时间同步**问题，一次上一个，出问题能二分定位。

## 5. 新增的坑（都来自教程，已被踩过）

| 坑 | 后果 | 对策 |
|---|---|---|
| 只传 pose 不带协方差 | 高刚度追抖动 → 接触力突变、脱手 | 传 (μ, Σ, t, frame, validity)，刚度随 Σ 调 |
| 相机与关节时间戳不对齐 | 末端轨迹锯齿 | 时钟同步 < 1 ms |
| 手眼标定当小事 | 0.1 mm 目标直接崩（标定误差 0.5–2 mm） | 单独标定 + 验证（棋盘格/AprilTag 全工作空间） |
| 用视觉位姿直接规划到 0.1 mm | 规划器以为能到，实际差 1–2 mm | 粗到细：视觉 → 伺服 → 接触搜索 |
| `addCollisionObjects` 后立刻规划 | 用旧场景，穿模 | 用 `applyCollisionObject()` |
| 力 PI 控硬表面 | 失稳振荡 | 用阻抗（无源性） |
| 触觉进策略环 | 20–160 ms 决策追不上 1–10 ms 事件 | 触觉只进 MCU / 控制层快环 |
| 三路传感器不同步 | 接触事件与关节位置错位 → 算错接触点 | 统一时间基准（PC MONOTONIC + MCU CYCCNT） |
