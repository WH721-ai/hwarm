## 2. 事故复盘：为什么"拉不住"

### 2.1 日志时间线

```
17:12:48.66  ★ 进入零重力（kp → 0，过渡 6.0 s）
17:12:56.48  joint1..6 全部「反馈过期（>200 ms 没有新的状态帧）」
17:12:56.48  Deactivating hardware components as their read cycle resulted in an error
17:12:56.49  ❌ Error while attempting mode switch when deactivating controllers
                in read cycle!
             ↑ **去激活失败**
17:13:56    （用户断电）
```

### 2.2 故障链

```
① USB-CAN 偶发 10~20 ms 写阻塞 → 控制环跑 47 ms
        ↓
② >200 ms 收不到状态帧 → read() 判定 stale → **不更新 pos_states_**
        ↓
③ read() return ERROR → ros2_control 试图在 **read cycle 里**切控制器模式
        ↓
④ "Error while attempting mode switch" → **去激活失败，硬件僵在半退出状态**
        ↓
⑤ write() 继续跑，tau_ff 仍按**冻结的 q** 计算
        ↓
⑥ 机械臂开始漂 → 真实所需力矩变化 → 冻结的前馈越来越错
        ↓
⑦ **正反馈** → 越飘越快 → 拉不住 → 只能断电
```

### 2.3 正反馈的定量证据

**joint3 的模型重力矩随 q3 单调下降：**

| q3 | 模型 g3 | tau_ff（冻结在 25°） | **多给** |
|---|---|---|---|
| 25° | 6.13 | 6.13 | 0 |
| 30° | 5.32 | **6.13** | **+0.81** |
| 40° | 4.18 | **6.13** | **+1.95** |
| 55° | 2.86 | **6.13** | **+3.27** |

**→ 越往上走，多给越多 → 加速 → 更往上。这就是"拉不住"。**

### 🔴 P1-2 反馈冻结后仍照算重力前馈（**已修**）

| 项 | 内容 |
|---|---|
| **现象** | stale 后 `pos_states_` 不更新，但 `write()` 仍按旧 q 算 `g(q)` |

### 🔴 P1-3 在 read cycle 里返回 ERROR → 去激活失败

| 项 | 内容 |

## 4. 为什么 kp=0 这么脆

### 4.1 带宽其实完全够

**零重力下只有 kd 阻尼：`M·dv/dt = −kd·v + τ_err`，时间常数 `τ = M/kd`**

| 关节 | 惯量 M | kd | 时间常数 | 对应带宽 |
|---|---|---|---|---|
| joint2 | 0.165 kg·m² | 1.5 | **110 ms** | 9.1 Hz |
| joint3 | 0.132 kg·m² | 1.5 | **88 ms** | 11.4 Hz |

**125 Hz（8 ms）有 8~11 倍余量 → 带宽不是问题。**

### 4.2 问题是"没有恢复力"

| 模式 | 稳定性来源 | 被打偏后 | 对长中断的反应 |
|---|---|---|---|
| **位置控制 kp=70** | 弹簧（位置反馈） | 拉回来 | 僵一下，**不发散** |
| **零重力 kp=0** | 只有阻尼 | **永不归位**，速度 = τ_err/kd | **误差放大 → 正反馈** |

**这就是本质：kp 提供自纠正，kd 只提供限速。**

### 4.3 误差放大有多快

| 关节 | 净误差 | 漂移速度 | 1 秒后偏角 | 那时误差 |
|---|---|---|---|---|
| joint2 | 0.08 N·m | 3.1 °/s | ~3° | ~0.2 N·m |
| joint3 | 0.30 N·m | 11.5 °/s | ~12° | **~0.8 N·m** |

**→ 几秒内误差翻倍，然后继续翻。**

| 优先级 | 事项 | 成本 | 效果 |
|---|---|---|---|
| **P0** | 重新构建，让源码指纹一致 | 5 分钟 | 后面所有结论的前提 |
| **P0** | **物理兜底**（软垫 + 吊带） | 半小时 | 失控时**不摔坏** —— 唯一真兜底 |
| **P1** | 修 P1-3（read cycle 里的去激活） | 1 小时 | 不再僵在"半退出" |
| **P1** | 加零重力超时（P2-1） | 30 分钟 | 无人看管也能自己退出 |

| **P3** | joint6 阻尼/偏置（P3-2） | 20 分钟 | 工具不自转 |
| **P4** | 换实体机 + RT 内核 | 半天 | 抖动 47 ms → ~10 ms |
| **P4** | 换 PCIe CAN / LinkX ENET | 钱 + 半天 | 摆脱 USB |

## 6. 结论

> **模型是对的，位形选对了，trim 也算对了 —— 但系统在"反馈中断"这条路径上不安全。**
>
> **零重力把位置反馈拿掉，等于拿掉了控制系统唯一的自纠正机制。
> 于是任何不完美都从"性能下降"变成"发散"。**
>
> **在补齐这三样之前不要试零重力：**
> **① 物理兜底 ② 读周期去激活修掉 ③ 零重力超时保护**
